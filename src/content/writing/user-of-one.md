At work I build for millions of users I will never meet. At home I build for one user, and I know him very well.

I expected the second job to be easier. It is not easier. It is more honest.

## There is no persona to hide behind

In a company, a weak idea can survive for months. Someone writes a persona. Someone finds a number that supports it. The idea ships, and nobody is sure whether it worked.

With one user, that does not happen. I either open the tool on Monday morning or I do not. There is no survey and no dashboard of adoption. The feedback is my own behaviour, and it arrives within a week.

## The dashboard I did not open

My best example is a failure. I built a status page for my life admin: every deadline, every open item, one screen.

I did not open it for weeks.

The page was complete, and that was the problem. It listed everything, including things that were waiting on other people. Reading it felt like work. So I avoided it.

The fix was not a feature. I cut the page down. The home screen now shows only short titles, and only things that are my move. Details sit one click away. Items that wait on someone else do not appear at all.

After that I started opening it.

## What I took back to work

Three habits came out of this.

**Watch behaviour, not opinions.** I would have told you the first dashboard was good. I also never used it. Only one of those facts mattered.

**Completeness is not a benefit.** A tool that shows everything asks the user to do the sorting. Most of the value is in what you leave out.

**Small and used beats large and correct.** Every system on this site started as the smallest thing that could hold one problem. The ones that grew did so because I kept using them.

None of this is new. I had read all of it before. I only believed it once the user was me.
